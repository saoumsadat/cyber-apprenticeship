# Cyber Apprenticeship

This repository is the working environment for a long-term, hands-on cybersecurity engineering apprenticeship.

The apprenticeship is run as an engineering relationship:

- **Intern:** builds, experiments, troubleshoots, documents practical work, and asks questions.
- **Senior Engineer:** defines assignments, teaches the underlying concepts, reviews work, maintains project state, and gradually increases responsibility.

## Objective

Build and operate a production-style application from the ground up while using it as a laboratory for software engineering, networking, Linux, infrastructure, cloud, application security, DevSecOps, monitoring, detection, and incident response.

The goal is not to memorize every technology. The goal is to develop a systems-level understanding of how modern software is built, deployed, secured, attacked, monitored, and maintained.

## Repository Areas

- `app/` — application source code
- `infrastructure/` — deployment and infrastructure configuration
- `security/` — security engineering, testing, hardening, and controls
- `labs/` — isolated experiments and learning exercises
- `docs/architecture/` — architecture and system-design documentation
- `docs/decisions/` — important engineering decisions and their reasoning
- `docs/learning/` — concepts and lessons that emerge during the apprenticeship
- `docs/incidents/` — incident investigations and postmortems
- `docs/networking/` — networking designs, diagrams, and notes

## Operating Principle

Every major phase should follow the cycle:

**Understand → Build → Test → Break → Investigate → Fix → Document → Review**

The repository is the long-term source of truth for apprenticeship progress. Markdown state files are maintained by the Senior Engineer so that future sessions can synchronize from the repository rather than relying on conversation memory.
